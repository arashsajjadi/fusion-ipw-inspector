# Development history

The true sequence of how Fusion IPW Inspector was built, reconstructed from the Git history,
the tags, the release dates and the test reports. Nothing here was backdated: the first two
versions were each committed as one commit at the end of their working session, and the
0.3.0 work was committed in grouped commits at the end of its session. Where a version was
built from many uncommitted steps, the steps are listed below in the order they happened.

All dates are local time (UTC−6). Fusion build 2.0.2705x (2705.1.15), Windows 11.

## v0.1.0 — 2026-09-25, one commit (`3af21d9`, 19:05)

Goal: click a point on the in-process stock and read X/Y/Z in any Setup WCS.

What was established, in order:

1. Research of the Fusion API around `Setup.workCoordinateSystem` (a setup-to-world rigid
   transform whose translation is in mm regardless of document units) and of viewport picking.
2. `core/transform.py` (`SetupFrame`), `core/point_inspector.py`, `core/stock_file.py`, with
   pure-Python unit tests.
3. The dialog: setup dropdown, point selection, X/Y/Z, Copy XYZ, Copy G-code, reference point.
4. Manual acquisition of the stock: the user saved the stock from Simulation (Save Stock) and
   loaded the STL through the dialog; the add-in placed it with the setup WCS.
5. Toolbar button in Manufacture > Inspect, icons generated by `tools/make_icons.py`.
6. Release v0.1.0 on GitHub, installed and tested on the watch-case job.

## v0.2.0 — 2026-09-25, one commit (`4cdbdcf`, 21:44)

Goal: eliminate the manual Save Stock step.

1. Investigation of 40 avenues to obtain the in-process stock programmatically, recorded in
   `docs/RESEARCH.md` (no public API returns it on this build).
2. The route that worked: Fusion exports the setup stock and part as STL for any post processor
   that sets `this.exportStock = true`. A helper post that writes no NC code
   (`resources/post/ipw_inspector_stock.cps`), a temporary NC program, `postProcess`, a sidecar
   `.ipwinfo`, the stock imported as a tagged temporary component.
3. Provider chain (`stock/post_export.py`, `stock/saved_file.py` with a folder watcher),
   `stock/mesh_validation.py`, the per-document session in `stock/acquisition.py`.
4. Findings that shaped the design: graphics and document changes made inside `inputChanged`
   are discarded, so document changes run in a dialog-less action command after which the
   dialog reopens with its state; `ConstructionPointInput.setByPoint` only accepts a bare point
   in direct designs, so reference points are anchored to a sketch point; setups created through
   the API lack `job_continueMachining`.
5. Compact dialog, source badge, self test command, the analytic validation script
   `tools/validate_in_fusion.py` (17 checks).
6. Release v0.2.0, installed and tested on the watch case (Setup2, Setup3, Setup5) and on the
   synthetic pocket job.

## v0.3.0 — 2026-09-25 23:00 to 2026-09-26 00:40, six grouped commits plus release commits

Goal: product-quality interaction, lifecycle and documentation without touching the validated
acquisition, transform and export core. The work happened in one continuous session; the
commits below were created at the end of that session (all timestamped 2026-09-26 00:34) and
group the changes by topic. The order in which things were actually done:

1. **Audit of 0.2.0** on the installed build: a blank window flashed on launch, the panel was
   long, picks landed on the raw hit under the cursor, the mesh was drawn with all its triangle
   edges, the WCS triad looked doubled after a few sessions.
2. **Transient window.** A monitor of the Fusion process' top-level windows (25 ms sampling)
   caught `Qt683QWindowIcon "IPW Inspector" 269x147` 6.3 s after launch: the progress dialog
   created during acquisition. Removed. Commit `4ab79e3`.
3. **Snapping core.** `core/mesh_index.py` (uniform grid, chunked build) and `core/snap.py`
   (plane clustering, corner/edge/surface reconstruction, rejections, tracker) written and
   benchmarked offline against the real 828 912-triangle Setup5 stock (load + build 1.87 s,
   hover 4.2 ms median). `tests/test_snap.py`. Commit `cd4309d`.
4. **Dialog redesign and hover preview.** `commands/snap_controller.py`, the rewritten
   `commands/inspector_command.py`, `ui/marker.py`, the preview glyph. First in-Fusion test
   showed a working EDGE preview on the watch-case rim.
5. **Bugs found and fixed while testing in Fusion** (all in the same files, so they are part
   of commit `eb1c01b`):
   - the triad labels were doubled because each dialog session left its graphics group behind;
     Fusion restores the last preview graphics when a command ends, so groups are now tagged and
     swept by a deferred custom event once the dialog has closed;
   - graphics created in `executePreview` are deleted by Fusion before the next preview, so
     nothing is cached across redraws;
   - no click produced a pick: requesting `doExecutePreview()` from inside `preSelectMouseMove`
     cancels the selection, so the hover preview is now drawn directly from the hover event;
   - custom graphics under the cursor could intercept the click: all markers are non-selectable;
   - Tab never reaches the command while the dialog owns keyboard focus: N cycles candidates;
   - a cycled candidate was overridden by the hover that Fusion fires right before a click:
     manual choices are sticky in the tracker (unit test added);
   - deleting the temporary stock from a document that is not active does not stick: a document
     switch closes the session and the stock is removed once its document is shown again.
6. **Stock display** without triangle edges and slightly translucent. Commit `a95fef7`.
7. **Verification on the installed build**: tab corners A, B and D, a tab edge, a tab face, a
   cycled edge (see README § 7 and `docs/SNAPPING.md`); Copy XYZ / Copy G-code with clipboard
   checks; setup switching Setup5 → Setup2; 10 monitored launches with 0 transient windows;
   open/close cycles, cancel, add-in reload while open, document switch, all with 0 leftover
   components and 0 leftover graphics; 403 hovers timed inside Fusion (2.1 ms median,
   4.1 ms p95); the analytic validation (17/17) and 52 unit tests re-run.
8. **Lifecycle script** `tools/lifecycle_test.py` (10 cycles, 0 failed). Commit `942cfb2`.
9. **Documentation**: README rewrite, `docs/SNAPPING.md`, CHANGELOG, demo GIF and screenshots
   captured from the 0.3.0 build, installer version reporting. Commit `0125803`.
10. This file, the version bump to 0.3.0 and the tag, then the release ZIP was built, installed
    from the ZIP and re-tested before publishing.

## v0.4.0 — 2026-09-26 14:00 to 15:30, grouped commits plus release commits

Goal: make hovering feel instantaneous and magnetic on the real Setup5 stock, without touching
the validated acquisition, transform and export core. One continuous session; commits created at
the end, grouped by topic. The actual order:

1. **Profiling first.** Every stage of the 0.3.0 hover pipeline was timed inside Fusion with a
   continuous cursor sweep: 17.7 ms per event (local reconstruction 4.6 ms, marker delete and
   recreate 5.7 ms, viewport refresh 7.2 ms), the pipeline saturated at 56 events per second, and
   Fusion's own cost per event outside the handler was small. So the display mesh was not the
   problem; the per-hover work was.
2. **Feature graph** (`core/features.py`): cell-plane clustering, union-find merge into patches,
   edges and corners from adjacency, coarse-cell lookup. Benchmarked offline on the real stock,
   then tuned: triangles that span several cells were being counted several times (fixed), the
   per-pair face-width test cost 4.4 s (replaced by a per-patch covariance), fillet strips made
   spurious edges (faces must be three cells wide across an edge). 1 056 corners, 2 555 edges,
   query 0.28 ms.
3. **Ray cast and magnetic tracker**: `MeshIndex.raycast`, `MagneticTracker`, geometric keys for
   the local fallback, unit tests.
4. **Controller and dialog**: hovering from `mouseMove` through the ray cast, clicks from
   `mouseUp` committed from an idle event, the display mesh non-selectable, persistent marker
   groups, Show IPW checkbox, startup and hover timing logs.
5. **Bugs found while testing in Fusion**: without an explicit viewport refresh the moved marker
   was not repainted (repaints are now throttled to 60 Hz with a deferred repaint); a light-bulb
   change inside the dialog's event did not stick (applied from an idle event); the overlay still
   pre-highlighted because the preSelect handler accepted it (now rejected there); the exporter's
   housekeeping deleted the cache file next to the STL on every export; the STL fingerprint changed
   on every export because Fusion leaves the attribute bytes undefined (now masked); the cache
   pickled class instances under Fusion's mangled module name (now plain data); a 10 mm tolerance
   step forgot the unit conversion (tolerance was 0.07 mm for a while).
6. **Measured on the installed build**: per event 2.3 ms median, 7.6 ms p95; 170 events per
   second sustained; six picks on the tab corners, edge and face exact to 0.0007 mm (0.0043 mm on
   the tessellated underside); magnetic hold recorded step by step; Show IPW on/off in 5–15 ms;
   17/17 analytic checks, 79 unit tests, 0 leftovers after close.

## v0.4.1 — 2026-09-26, one fix found right after publishing 0.4.0

The release-ZIP acceptance screenshots still showed the stock tinted while hovering. The
overlay was non-selectable and rejected in `preSelect`, but the pick input's `MeshBodies`
selection filter alone makes Fusion pre-highlight matching bodies. With model selection off the
input now carries a filter that never matches the stock; the overlay keeps its shading and Fusion
does no per-move work on it. Verified on the installed build, then released as 0.4.1.

Checked afterwards: the overlay's colour still differed between sessions (pink, orange, yellow,
green) but stayed constant while hovering, so it was not a highlight but Fusion's *Component
Color Cycling* applied to the freshly imported component. Assigning a library appearance to the
mesh body did not override it, so that experiment was reverted and the behaviour is documented in
the README instead.

## Conventions from here on

Granular conventional commits as work happens (`fix(ui): …`, `feat(snap): …`, `test(…): …`,
`docs: …`, `release: …`), a CHANGELOG entry per version, and a row in README § 7 whenever the
transform or the snapping rules change.
